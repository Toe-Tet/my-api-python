# My API

## Migrations

### Shared Database

Create a shared database migration from shared models:

```bash
uv run alembic revision --autogenerate -m "your message"
```

Create a manual empty shared migration:

```bash
uv run alembic revision -m "your message"
```

Run shared database migrations:

```bash
uv run alembic upgrade head
```

Rollback the latest shared database migration:

```bash
uv run alembic downgrade -1
```

### Tenant Databases

Create a manual tenant migration:

```bash
uv run alembic -c alembic_tenants.ini revision -m "your message"
```

Create an autogenerated tenant migration from tenant models:

```bash
uv run alembic -c alembic_tenants.ini -x url="postgresql+psycopg://USER:PASS@HOST:PORT/tenant_db_name" revision --autogenerate -m "your message"
```

This needs one real tenant database URL so Alembic can compare the current database schema with the tenant models.

Run tenant migrations for all tenants:

```bash
uv run python migrate_tenants.py upgrade head
```

Rollback the latest tenant migration for all tenants:

```bash
uv run python migrate_tenants.py downgrade -1
```

Run tenant migrations for one specific tenant database by URL:

```bash
uv run alembic -c alembic_tenants.ini -x url="postgresql+psycopg://USER:PASS@HOST:PORT/tenant_db_name" upgrade head
```

### Notes

- Shared database migration files are stored in `app/data/alembic/versions`
- Tenant migration files are stored in `app/data/alembic_tenants/versions`
- New tenant databases created during registration are already migrated by the registration flow
- `uv run python migrate_tenants.py upgrade head` is mainly for applying newer tenant migrations to existing tenants
